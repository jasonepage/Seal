Check the record yourself

The promise that matters least is the one you have to take on faith. This page is the one you do not.

What a capsule is

Anybody holding part of somebody's estate can export a capsule: one JSON file carrying the entire signed history. Every public key involved, every event in order, each one signed and hash linked to the one before it, the timestamp tokens where they were obtained, the wrapped key material with its commitments, and optionally the encrypted envelopes themselves.

Nothing in a capsule is readable without private keys that live in people's phones. A capsule can be posted on a public website without harm. That is deliberate. It is the archive of record and it has to survive being copied around, emailed to a lawyer, and sitting on a hard drive for twenty years.

What the verifier checks

tools/verify_capsule.py is a single Python file with no Seal in it and no network access. It checks:

  • Every event's signature, against the device key that signed it, using P-256 ECDSA with SHA-256.
  • That every device key was endorsed by the identity that claims it, and that the endorsement is itself a valid WebAuthn assertion with the right relying party and the user presence bit set.
  • That the hash link from each event to the one before it holds, so nothing has been removed from the middle.
  • Every RFC 3161 timestamp token against the authority's certificate, and that the token covers the digest it claims to.
  • That each key holder's share matches the commitment published for it in the signed epoch statement, so a bad share names the person who submitted it.

Run it

git clone https://github.com/jasonepage/Seal
cd Seal
python3 tools/verify_capsule.py seal-capsule-XXXX.json

Add --strict to fail on anything it would otherwise warn about, including a missing timestamp token. The script reads the file, prints a line per check, and exits non-zero if anything does not hold.

There is also tools/make_test_capsule.py, which builds a synthetic capsule so you can watch the verifier pass, then change one byte and watch it fail. That is a more convincing five minutes than anything on this website.

Why this is the important page

Every other claim here is a sentence. This one is a file, a script, and an exit code. If this project ends tomorrow, the capsule format is documented in docs/CAPSULE.md in enough detail to write a fresh verifier from scratch, and the document is written for somebody who has never seen Seal and has only the file and a laptop.

What the verifier cannot tell you

It proves that a particular credential did a particular thing at a particular time, and that the record has not been edited. It does not prove that the person holding that credential was who you think. Binding a credential to a human being is what standing next to them does, and after that it is what notaries are for.

It also cannot prove that nothing is missing from the record on its own. Hiding an event is detectable, but only by comparing capsules held by several different people, or through the timestamp tokens. That limit is stated in the threat model rather than glossed over. The limits are here.
