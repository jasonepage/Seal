Check the record yourself

Every other claim on this site is a sentence. This one is a file, a script and an exit code.

What a capsule is

Anybody holding part of somebody’s estate can export a capsule: one JSON file carrying the whole signed history, the public keys, the wrapped key material with its commitments, the timestamp tokens, and optionally the encrypted envelopes. The full contents are listed here.

Nothing in it is readable without private keys that live in people’s phones, so a capsule can be posted on a public website without harm. That is deliberate. It is the archive of record and it has to survive being copied around, emailed to a lawyer, and sitting on a hard drive for twenty years.

Run it

pip install cryptography
git clone https://github.com/jasonepage/Seal
cd Seal
python3 tools/verify_capsule.py seal-capsule-XXXX.json --strict

tools/verify_capsule.py is a single Python file with no Seal in it and no network access. Its only dependency is the cryptography package. It prints one line per check and exits non-zero if anything does not hold. Without --strict it passes a timestamp token whose signature it could not check, and says so on that line.

There is also tools/make_test_capsule.py, which builds a synthetic capsule with real signatures, so you can watch the verifier pass and then run it again with --tamper and watch it fail.

What it checks, in order

  • Every device endorsement verifies under its identity’s root public key: a WebAuthn assertion over the endorsement commitment, with the relying party hash, the user presence bit and the clientData type all enforced.
  • Every event’s digest recomputes from its own fields; its P-256 signature verifies under the device key it names; that device is an endorsed device of the actor it names; and that actor is allowed to write that kind of event.
  • Every event’s link to the one before it names an event that is present in the capsule, or is empty.
  • Every epoch event’s commitments match the epoch material blob, and that blob’s digest matches what the owner signed.
  • Every key tap verifies under that key holder’s root key, over the release challenge naming that exact claim and that exact record head.
  • A release’s Estate Key matches the commitment the owner published for it.
  • Every RFC 3161 token: the status is granted, the token carries that event’s digest, and its time is printed. If openssl is on the path, the token’s signature is checked against the certificate inside it.

Whether that certificate’s issuer deserves trust is a decision for the reader, and the script says so rather than deciding for you. The authority Seal points at today is a placeholder.

What the verifier cannot tell you

It cannot prove the record is complete. The owner and several key holders write to it at the same time with no server to order them, so the record is a hash linked graph rather than one strict chain. Checking every link proves that each event points at an event that is present. It does not prove that nothing was left out by whoever built the file. Hiding an event is detectable, but only by comparing capsules held by different people, or through the timestamp tokens, which prove an event existed no later than the time they name.

It cannot check a share against its commitment. The shares in a capsule are wrapped to their key holders’ devices, so the script checks that the commitments in the epoch material are the ones the owner signed, and nothing more. Catching a bad share is done later, by the claimant’s phone at the moment of release, and a bad one names the key holder who submitted it.

It cannot prove who anybody is. It proves a particular credential did a particular thing at a particular time. Binding a credential to a human being is what standing next to them does, and after that it is what notaries are for.

If this project ends

The capsule format is documented in docs/CAPSULE.md in enough detail to write a fresh verifier from scratch, for somebody who has never seen Seal and has only the file and a laptop. The script also takes --combine, which recovers the Estate Key from raw shares for a family whose phones are gone.
